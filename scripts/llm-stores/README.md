# sa-llm-stores-tooling

Tooling to submit the **ServicesArtisans RGE-OS** open-data assets (datasets,
spec, ontology, APIs) to the main "LLM stores" — the public registries and
indexes consumed by AI agents / LLMs / web crawlers to discover trustworthy
data sources.

This is **pillar 11** of the RGE-OS manifesto (`docs/RGE-OS-MANIFESTO.md`).
Sprint 1 (this commit) ships **dry-run tooling**: every CLI generates the
store-specific manifest on disk (`manifest-out/<store>/`) and prints a
summary. Sprint 2 will wire the actual HTTP submissions behind
`--no-dry-run` + env-gated tokens (no token committed).

## Why

Even with the best APIs (MCP, REST, GraphQL, SPARQL, AnswerEngine), if Gemini
/ Claude / GPT / Perplexity agents can't _discover_ the endpoints when a user
asks "trouve un artisan RGE a Lyon", the surface is invisible. Submitting to
llms.txt + data.gouv.fr + Google Dataset Search + the AI plugin/MCP
registries closes that gap.

## Usage

```bash
# Dry-run all stores at once (default)
node bin/submit-all.mjs --dry-run

# Or one store at a time
node bin/submit-llmstxt.mjs --dry-run
node bin/submit-data-gouv.mjs --dry-run
node bin/submit-google-dataset.mjs --dry-run
node bin/submit-hf.mjs --dry-run
node bin/submit-mcp-registry.mjs --dry-run
node bin/submit-chatgpt-plugin.mjs --dry-run
node bin/refresh-wikidata-stub.mjs --dry-run

# Override output dir
node bin/submit-data-gouv.mjs --dry-run --out /tmp/data-gouv
```

Every CLI defaults to `--dry-run=true`. Pass `--no-dry-run` only once
Sprint 2 wiring is reviewed.

## Output

`manifest-out/` is gitignored. Layout:

```
manifest-out/
  llmstxt/llms.txt
  data-gouv/<slug>.json
  google-dataset/<slug>.jsonld
  hf/<id>-README.md
  mcp-registry/application.json
  chatgpt-plugin/ai-plugin.json
  wikidata/quickstatements.txt
```

## Tests

21+ tests covering each builder (presence of mandatory fields, CC-BY 4.0
license, /transparence-ia disclosure pointer, schema.org / MCP / OpenAPI
contracts).

## Zero dependencies

Pure Node 18+ — `parseArgs`, `node:test`, `node:fs/promises`. No `package.json`
dependencies. No npm install required.
